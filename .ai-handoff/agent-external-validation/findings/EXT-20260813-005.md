# AnyChain Agent External Validation Record — EXT-20260813-005

At the "Enter the custom RPC method name to validate" prompt, a
well-known RPC method that IS ALREADY IN THE DEFAULT WORKLOAD
(`eth_getBalance`, which is one of `eth_getBalance=25` /
`eth_getTransactionCount=25` / `eth_blockNumber=25` / `eth_gasPrice=25`
per the ethereum default mixed weights) is rejected with the generic
"clarify unmapped" template. The user is then offered only "Cancel
the complete pending plan" as an option. This is confusing because:
(a) the RPC method IS a real, valid ethereum method that the framework
already knows about, and (b) a "custom RPC method" name entry field
should not silently reject known method names — it should either
accept them or explicitly say "this method is already in the default
workload; use `adjust weights` instead".
